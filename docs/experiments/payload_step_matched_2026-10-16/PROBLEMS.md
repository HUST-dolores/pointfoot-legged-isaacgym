# 计划审计问题与补测前置条件

日期：2026-10-16。下列保留计划阶段发现的旧入口风险；随后已用独立入口完成补测，
不修改这些公共脚本。具体处理及新预检问题见`RUN_STATUS.md`，真实结果见`RESULTS.md`。

## 已确认的事实

1. 旧目录 `payload_motion_metrics_2to6kg_2026-07-21` 的四个 MAT 实际固定质量
   5.9268727 kg；目录名不是质量扫描证据。旧 `CONFIG_AUDIT.md` 已明确纠正。
2. 四个保存的 env_cfg 除方法的五个输入/残差/维数字段及训练 seed 外一致；
   train_cfg 除 encoder 维数、残差标志、run_name 与 seed 外一致。
   两方法的不同输入是原实验方法组成，不能在补测中偷偷统一架构。
3. 原来选用的 MG s1 检查点为 11000，不是其另一个确实存在的 16000。
   本轮保持原选择，不能事后改成胜出的检查点，但需声明更新预算不等。
4. `base_task.py::_process_rigid_body_props` 将 `props[0].mass/com` 写入
   base_mass0/base_com0；`_compute_mass_com` 更新等效基座组合量。
   `wheelfoot_flat.py::compute_group_observations` 以它们的增量作为监督，
   不是用逐连杆全身质心或箱体位置作为监督。

## 现有评测入口不能直接充当新实验

- `play.py::_apply_saved_env_cfg` 恢复关键维数和部分字段，不是完整旧配置恢复器。
  后续若直接继承当前任务默认值，控制、归一化、新功能开关可能漂移。
- `play.py` 在推理之后重写命令，环境内部仍可周期重采样。旧分析将这种帧剔除，
  新实验必须在命令采样入口固定，并验证 actor 看到和实际执行的一致。
- 当前 `play.py` 的 all-env 字典已经包含轮接触力与质心增量等字段，
  不能说“当前脚本完全没有这些日志”；但是旧归档不含完整所需信息，
  当前入口也没有本实验所需的完整配对场景、第一条轨迹事件和 reset 前终端快照。
- 当前 all-env logger 再次调用 `is_load_on_body`，默认会更新滞回状态；
  环境一步内本已更新，记录器不应再推进一次。必须只读缓存标签。
- 当前 all-env logger 将离体后的箱体相对位置写成 0，不适于确认真实掉载。
  补测必须保留未门控的箱体世界/相对位姿，以及标签与物理事件的区别。
- `env.step` 的 post-physics 阶段内部会自动 reset。返回之后的根状态不一定
  是触发 done 的失败状态，只有记录 done 而不抓终端快照仍可能遗漏失效证据。
- `analyze_payload_motion_metrics.py` 依赖 loaded mask、外部传入固定 step 命令、
  存在的加载样本，不支持本轮空载基线、严格共同时间窗配对或完整事件分母。
  不能用旧脚本不加修改直接得到本轮主表。
- `measure_load_estimation_walk.py` 会改变负载质量采样模式、关闭噪声，并将估计
  先按时间平均再算误差；它不是本轮逐时间样本 RMSE 的直接实现。

## 待预检后冻结，而非已有证据

- 公共通道噪声和全部物理随机化的逐环境配对表尚未生成/验证。
- 真实掉载的支撑几何范围需要由本轮实际碰撞模型确认；0.20 s 为拟采用的
  持续时间阈值，须在正式方法比较前冻结，不根据结果修改。
- 目前没有新 GPU 吞吐测量，因此没有可信墙钟 ETA；累计 8 h 环境时长不是 ETA。
- 二次训练重复不足以可靠刻画训练总体置信区间；多环境、多评测 seed 不能替代。
- 带载减空载不等于纯估计器因果消融；本轮不宣称解决该独立问题。
