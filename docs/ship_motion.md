## 物理模型

复用原先预留的负载 actor 作为甲板，机器人和甲板使用真实 simulation-domain 索引。
该任务不支持同时添加自由负载；正常负载和前跳任务仍使用原来的小箱子。
甲板是关闭重力的 10000 kg 动态盒体。每个 physics tick（不是仅 policy tick）
写入一致的位姿、线速度和世界角速度，旋转中心是甲板上表面中心。
这是一种外部强制运动近似，不是 PhysX kinematic target。接触反作用在步内仍会
改变甲板状态，因此应检查 probe 的位置跟踪误差、步长敏感性，再提高频率和幅值。
没有额外静态地面托住机器人；跌落、超出甲板和低机身高度会触发 reset。
GPU reset 与甲板更新在下一 simulate 前合并为一次 root-state setter。

## 策略输入

普通观测固定 37 维：机器人角速度 3、重力投影 3、关节角 6、关节速度 8、
甲板 IMU 9、上一动作 8。甲板 IMU 的 slice 是 `[20:29]`，直接进入 actor 和
encoder 历史；critic 前 7 维保留速度／质量／质心监督，再接同一份普通观测。
不向 actor 提供运动相位、目标波形或未来数据。

IMU 是甲板坐标系角速度 3、加速度计比力 `R^T(a-g)` 3，以及理想化姿态估计器
的重力方向 3。后者不等于晃动中的原始加速度计读数。加速度由实际刚体速度差分，
并计入安装偏置的角加速度和向心项。默认延迟一帧（20 ms），可配置噪声。
`ship.imu_enabled=False` 会同时清零 actor、critic 普通观测和历史中的这 9 维，
作为无甲板传感器的对照。真实部署需对应的姿态估计与同步链路，不能直接替换成真值姿态。

速度跟踪使用相对甲板接触位置的速度 `v_robot - (v_deck + omega x r)`。
机身高度使用甲板法向距离；原地保持位置使用甲板坐标。姿态奖励仍要求机身相对世界重力直立。

## 运行

在本 worktree 根目录运行，使用有 Isaac Gym、PyTorch 的 Python 环境。
设置 `PYTHONPATH`，避免 editable install 指向旧 codesign 工作目录。

```bash

python legged_gym/scripts/ship_motion_probe.py --mode probe --device cpu --imu-off --output /tmp/ship-probe-noimu
python legged_gym/scripts/ship_motion_probe.py --mode train --device cpu --iterations 2 --output /tmp/ship-train-smoke
python legged_gym/scripts/ship_motion_probe.py --mode eval --device cpu --checkpoint /tmp/ship-train-smoke/model_2.pt --output /tmp/ship-eval
python legged_gym/scripts/train.py --task wheelfoot_ship --headless --num_envs 512
```

`probe` 检查真实轮子接触、有限观测值、actor 直连 IMU、IMU 对照开关、索引和甲板运动。
其零动作 PD 控制不是已训练策略，机器人跌倒／reset 不代表链路失败。
`train` 模式使用缩小网络验证 PPO 更新与 checkpoint，不能据此声称剧烈摇晃平衡成功。
正式实验需要相同预算、多种 seed 的有／无 IMU 对照，并在固定幅值频率网格统计
存活时间、跌倒率、姿态误差、相对甲板漂移和速度误差。训练幅值默认较小；
不要把“调大参数”当作“已经验证剧烈摇晃”。

### 奖励定义：航向变化速率，不是绝对航向锁定

新增可选`--heading-yaw-tracking-scale 2`，对应`_reward_ship_yaw_rate`：
`2 * exp(-(heading_rate - yaw_rate_command)^2 / 0.25)`，本组command=0rad/s。
其中f=机器人前向轴旋转到世界坐标，fdot=omega_world×f，
heading_rate=(f_x*fdot_y-f_y*fdot_x)/(f_x²+f_y²)，单位rad/s；分母最小1e-6
防止翻倒时的奇异值，原翻转/低高度终止仍保留。实际机身状态只用于奖励和
诊断，**未作为新观测输入**，不提供真实yaw角/绝对航向误差。

与原可选`--yaw-tracking-scale`的body gyro z奖励区分，旧接口保留以复现yaw2
历史实验，两个接口不可同时启用。默认不启用新奖励，因此既有配置/旧模型
语义不变。该奖励约束“不持续旋转”，并不直接保证最终角度回到初始朝向；
后续同时报告累计yaw漂移，不能用速率较小替代航向保持或零失败。

### 可测量输入与模型假设

`utils/ship_model_prior.py` 只接收带原有噪声/延迟的甲板IMU、本体现有陀螺仪/
重力投影测量缓存、六个腿关节位置、左右轮接触力模长，以及标定URDF和轮半径。
接触标志使用5N接通/2N断开的滞回；这是理想仿真接触检测，部署需要实际的接触
传感/估计。先验不会读取仿真root四元数、世界轮心位姿、真实甲板速度、未来
正弦波相位、频率或未来仿真状态。已有本体噪声仍加在原始20维观测上；新特征
来自测量缓存和滤波，不额外叠加一份独立白噪声，不能宣称等同于直接在最终
加噪actor输入上计算的特征。

相对姿态 `R_BD` 由初始航向标定、双端陀螺仪积分和重力方向校正得到。
`initial_relative_yaw_rad` 默认为0（初始机器人/甲板航向对齐）。两路重力不能
观测相对yaw；后续yaw会受陀螺仪偏置漂移影响，不能用仿真真实heading纠正。

值宣传为无延迟的真实未来姿态。反复读取观测不积分：只在每个策略tick更新一次。

接触平面在当前受支撑接触点的加权中心附近预测转动；沿当前法向求左右接触
点的差动位移，保留轮式运动的切向自由度，并计入轮半径/法向变化。没有接触
的腿不生成支撑参考。**这不是绝对接触轨迹或升沉预测**：当前输入不能唯一
确定甲板平移速度和真实转动中心；公共升沉/平移补偿仍由策略处理。
